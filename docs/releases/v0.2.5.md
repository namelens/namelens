# NameLens v0.2.5 Release Notes

Release date: 2026-05-29

## Highlights

**Theme: make `--expert` trustworthy.** The `--expert` flow is the value
proposition of NameLens. v0.2.4 shipped it, but in dogfooding it was where most
of the friction lived. v0.2.5 closes the trust gap with four targeted PRs:

- **`--timeout` flag on every AI-invoking command** — `check`, `generate`,
  `mark` (text + image legs), `compare`, `review`. Same shape, same semantics
- **`ailink.default_timeout` raised `60s` → `180s`** — matches realistic budgets
  observed in dogfooding; driver-layer ceiling fix lets per-call `--timeout`
  flow through without re-clamping
- **JSON `expert` field parity with markdown** — `--output-format json` now
  surfaces the synthesized expert digest, sharing the same single-source
  synthesizer as the markdown renderer
- **`--expert-bulk` reliability fixes** — centralized name canonicalization
  closes a silent-merge-miss; `waitForFallbackSlot` closes the ctx-cancel
  slot-drop hole so every requested name gets a populated batch slot

Origin: the 2026-05-08 recipekit dogfood session surfaced four classes of
friction — JSON/markdown shape mismatch on `--expert`, 60s timeouts on realistic
loads, silent merge misses in `--expert-bulk`, and inconsistent deadline
coverage on `compare`/`review`/`mark`'s text leg.

## `--timeout` Flag Uniform Across Commands

**Status**: Added (and refined across PRs)

Every AI-invoking command now accepts `--timeout <duration>` with the same
help-text shape:

| Command              | Help text                                                                                       |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| `check --timeout`    | Per-call ailink timeout for expert/phonetics/suitability                                        |
| `generate --timeout` | Per-call ailink timeout                                                                         |
| `mark --timeout`     | Per-call ailink timeout applied to both the mark-prompt text leg and each image-generation call |
| `compare --timeout`  | Per-prompt ailink timeout for phonetics/suitability stitched analyses                           |
| `review --timeout`   | Per-prompt ailink timeout for the stitched review prompts                                       |

```bash
namelens check acmecorp --expert --timeout 240s
namelens generate "agent gateway" --depth deep --timeout 4m
namelens mark acmecorp --color brand --timeout 3m
namelens compare alpha beta gamma --timeout 180s
namelens review acmecorp --mode brand --timeout 240s
```

`--timeout` overrides `ailink.default_timeout` for that single invocation. `0` =
use config default.

### `mark` text-leg coverage

`mark`'s `--timeout` flag was added in v0.2.4-era work (#6 / PR-2) but initially
only bounded the image-generation call. PR-4 (#8) threads the flag through the
shared `runReviewGenerate` helper into the text-prompt leg too. Help text
updated accordingly.

This closes prodmktg's `review` brand-mode silent-prompt evidence — the text leg
can now be bounded with a known deadline.

## ailink Default Timeout 60s → 180s

**Status**: Changed

`ailink.default_timeout` raised from `60s` to `180s` in
`config/namelens/v0/namelens-defaults.yaml:47` and the embedded copy at
`internal/config/embedded/namelens/v0/namelens-defaults.yaml`.

### Why

The 2026-05-08 dogfood session observed timeouts at 60s on:

- Anthropic `--depth deep` `generate` with a ~5KB brief (provider latency on
  deep reasoning)
- `check --expert-bulk` over 10 names (provider has more work to do per call)

Every fallback path observed in the session was rooted in 60s being too short.
`180s` was chosen to give Anthropic deep reasoning and 10-name bulk a
comfortable budget without blocking interactive use.

### Driver-layer ceiling fix

A subtle bug compounded the symptom: the registry was setting
`client.Timeout = ailink.default_timeout`, which re-clamped any service-level
deadline longer than the default. Service callers passing a longer `TimeoutSec`
would silently get the default ceiling.

Fix: `client.Timeout = maxTimeout` (the service-level clamp ceiling). Because
`context.WithTimeout` only shortens, any service-level deadline ≤ `maxTimeout`
passes through unmodified; bypass callers still get a hard ceiling. Confirmed by
`TestDriverForUsesMaxTimeoutCeilingNotConfigDefault` in
`internal/ailink/registry_test.go`.

## JSON Expert Field Parity

**Status**: Fixed

`namelens check acmecorp --expert --expert-depth quick --output-format json`
previously returned a result with no `expert`/`risk` field; the same call with
`--output-format markdown` rendered the full expert row. JSON-consuming agents
and pipelines were blind to trademark/conflict intelligence.

### Fix

Added a synthesized `Expert *ExpertDigest` field on `core.BatchResult`,
populated by a single render-time synthesizer in `internal/core/expert.go`
(`NewExpertDigest`). Both the markdown renderer and the JSON output now consume
the same synthesizer, eliminating the shape divergence.

The synthesizer is a pure pass-through:

```go
digest.Status = "risk: " + level
```

No transformation rule — `risk_level` from the AI response surfaces verbatim in
both markdown and JSON. This is the load-bearing property that closes NAM-001
(the risk-level inflation report from 2026-05-15): source-side, the renderer
cannot inflate.

### What you get

JSON output for `check --expert` now includes:

```json
{
  "name": "acmecorp",
  "ailink": { ... existing payload ... },
  "expert": {
    "status": "risk: medium",
    "risk_level": "medium",
    "notes": "...",
    "raw": { ... }
  }
}
```

Existing fields (`ailink`, `ailink_error`) are unchanged — `expert` is additive.
Same shape applies on `check --expert-bulk` and any `compare`/`review` JSON
outputs that surface expert data.

## `--expert-bulk` Reliability

**Status**: Fixed

Two bugs surfaced in the 2026-05-08 dogfood session:

### 1. Silent merge miss on mixed-case names

`Expert fallback scheduled` logged for one name; the response contained
`expert: null` for **all** names in the batch. ~40% expert-call failure rate
even on `--expert-depth quick` per-name.

Root cause: three different name keyings across three code paths:

- lookup used raw input
- live bulk map used `strings.ToLower(strings.TrimSpace(...))`
- cached bulk map used raw item name

The three keys disagreed on mixed-case input → silent miss on merge.

Fix: centralized canonicalization in `internal/cmd/expert_bulk.go`:

- `expertBulkKey(name string) string` — single canonicalization helper
- `bulkItemsToMap(items []BulkItem) map[string]BulkItem` — single helper for
  live + cached bulk map construction

All three paths (lookup, live-merge, cache) now route through the same
canonicalization. Mixed-case input merges reliably.

### 2. Ctx-cancel slot-drop

`namelens check ... --expert-bulk` with Ctrl-C during the fallback cooldown
previously produced a missing batch slot (nil entry) for the canceled name.
Downstream consumers that assumed every requested name had a slot broke.

Fix: `waitForFallbackSlot` now returns `AILINK_FALLBACK_CANCELED` on context
cancellation and falls through to the standard `summarizeResults` write path.
Every requested name gets a populated batch slot — error-tagged if the fallback
was canceled, but never nil.

### Tests

Seven new tests in `internal/cmd/expert_bulk_test.go`:

- Mixed-case input through bulk + fallback
- Whitespace-trimmed input through bulk + fallback
- Cancel-during-cooldown produces error-tagged slot, not nil
- Lookup/live/cached keying parity

## `runReviewGenerate` Timeout Convergence

**Status**: Added

`runReviewGenerate` in `internal/cmd/review.go` is the shared helper that backs:

- `compare` (phonetics + suitability stitched analyses, 2 sites)
- `mark` (text-prompt leg, 1 site)
- `review` (phonetics + suitability + stitched-mode dispatch, 3 sites)

Pre-v0.2.5, the helper had no `timeoutSec` parameter — its callers had no way to
thread `--timeout` to the underlying `service.Generate` call. PR-4 (#8) adds
`timeoutSec int` to the helper signature and updates all 6 callers.

### Diff scale

`+37/-13` across 4 files. The convergence is surgical — the function itself only
needed the parameter and one line inside (the `service.Generate(...)` call
gained `TimeoutSec: timeoutSec`).

### `--timeout` flags added

`compare` and `review` previously had no `--timeout` flag of their own. PR-4
adds both, mirroring the shape used by `check` and `generate` (same Duration
parsing via `timeoutFlagToSec` helper, same help-text template).

### Tests

Two new smoke tests in `internal/cmd/timeout_test.go`:

- `TestCompareCmdExposesTimeoutFlag`
- `TestReviewCmdExposesTimeoutFlag`

Mirror the existing three (`Check`, `Generate`, `Mark`) — guard against
init-block regression on flag presence. Service-level deadline-honoring is
covered by `TestServiceGenerateHonorsRequestTimeoutSec` in
`internal/ailink/search_test.go`, which exercises the
`GenerateRequest{TimeoutSec: N}` field directly.

## Deferred to v0.3.x

Tracked in `.plans/active/v0.3.0/expert-call-reliability-brief.md`:

- **Per-depth timeout policy** — different deadlines for `quick`/`deep` to match
  provider behavior
- **Retry policy with backoff** — symmetric to the bulk-fallback path
- **Streaming responses + partial-result on timeout** — currently a timeout
  returns no payload; streaming would let a partial response surface what the
  provider produced before the deadline
- **Async / background expert tasks** — for batches large enough that even 180s
  isn't comfortable
- **Bypass-caller lint rule** — currently the only guard on "did you thread the
  timeout?" is per-site review. A lint rule on Driver-method bypass callers
  would catch this class structurally

## Upgrade Notes

No breaking changes. All v0.2.4 configurations remain valid.

If you've pinned `ailink.default_timeout` to `60s` explicitly in your config, no
change — your pin holds. If you relied on the implicit `60s` default, you'll get
`180s` now; observable behavior is that previously-timing-out calls will
complete rather than fail. If you specifically want the old default back, pin
`ailink.default_timeout: 60s` in your config.

JSON consumers of `check --expert` output will see a new `expert` field on
results that have expert payload. Existing fields (`ailink`, `ailink_error`) are
unchanged — the new field is additive.
