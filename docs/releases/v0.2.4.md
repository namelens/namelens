# NameLens v0.2.4 Release Notes

Release date: 2026-05-05

## Highlights

v0.2.4 was originally prepared in March around two stability fixes (B13/B14);
the release picked up material from three subsequent dogfood-driven sessions
before tagging. Net scope: stability hardening + small CLI ergonomics +
supply-chain hygiene.

- **B13 fix**: `check --expert` works outside git repos via embedded schema
  fallback
- **B14 fix**: expert-bulk rate-limit burst mitigated with serialized fallback,
  cooldown spacing, and exponential backoff
- **`check --provider`**: provider override flag now matches the equivalent on
  `generate` — no more env-var workaround for A/B'ing AI backends
- **Vulnerability dependencies cleared**: Go toolchain pinned to 1.26.2 and
  `golang.org/x/image` bumped — `goneat dependencies --vuln` returns 0 findings
- **YAML tooling alignment**: `.yamlfmt` and `.yamllint` added at repo root to
  stop the goneat ↔ yamlfmt comment-padding oscillation
- **CI infra**: runner image bumped to `goneat-tools-runner-glibc:v0.4.0` (Go
  1.26.2 + bundled `golangci-lint v2.12.1`); redundant CI install step removed
- **`make pr-final`** strict-local-gate target so contributors can verify the
  same checks CI runs before pushing PR updates

## Expert Prompt Loading (B13)

**Status**: Fixed

Running `check --expert` from outside a git repository (e.g. from a
`make install` binary in `/usr/local/bin`) failed with "failed to load prompts"
because both `catalogForSchemas()` in `prompt/loader.go` and
`buildSchemaCatalog()` in `cmd/ailink_helpers.go` required a repository root to
locate schema files.

### Root Cause

The prompt loader and response schema catalog both used `findRepoRoot()` to
locate `schemas/ailink/v0/*.json` files. When running from an installed binary
outside the repo tree, `findRepoRoot()` returns an error and schema loading
fails entirely.

### Fix

Embedded prompt and response schemas via `go:embed` with temp-directory
extraction fallback, following the config layer's `standaloneAssetsRoot()`
pattern:

- `internal/ailink/prompt/loader.go`: Embeds `prompt.schema.json`, falls back to
  extracted temp dir when `findRepoRoot()` fails
- `internal/ailink/embedded_schemas.go`: New file embedding all
  `ailink/v0/*.json` response schemas via `embed.FS`, with `fs.WalkDir`
  extraction to temp dir
- `internal/cmd/ailink_helpers.go`: `buildSchemaCatalog()` falls back to
  `ailink.StandaloneSchemaCatalog()` when repo root unavailable

Makefile `sync-embedded-config` and `verify-embedded-config` targets extended to
keep embedded copies in sync with source-of-truth schemas under `schemas/`.

### Verification

```bash
make install
cd /tmp
namelens check testname --expert
# Should succeed without "failed to load prompts" error
```

## Expert Bulk Rate-Limit Burst (B14)

**Status**: Fixed

The first name in a multi-name `--expert` batch occasionally got "provider
request failed" due to rate-limit burst immediately after the bulk request
completed.

### Root Cause

When `--expert-bulk` completes a batch request, individual fallback requests for
names not covered by bulk results fire immediately and concurrently. This burst
can trigger provider rate limits (HTTP 429), causing the first fallback name to
fail.

### Fix

Layered mitigations in `internal/cmd/check.go`:

1. **Staggered scheduling**: post-bulk fallback requests scheduled with 2s
   initial cooldown and 1.5s spacing from bulk completion time
2. **Serialized execution**: fallback requests mutex-serialized to prevent
   concurrent provider calls
3. **Exponential backoff**: rate-limited (429) responses trigger retry with
   2s/4s/8s base backoff, up to 3 attempts, with deterministic per-name SHA256
   jitter (±300ms window)

### Verification

```bash
namelens check alpha beta gamma delta --expert --expert-bulk
```

## `check --provider` Flag

**Status**: Added

`namelens generate` already accepted `--provider <id>` to swap the AILink
provider for a single run. The same affordance was missing on `check`, forcing
users to fall back to `NAMELENS_AILINK_DEFAULT_PROVIDER` env vars to A/B test AI
backends. This release adds the flag with parity validation:

```bash
namelens check acmecorp --expert --provider namelens-anthropic
namelens check acmecorp --expert --provider namelens-xai --expert-depth deep

# Validation: unknown / disabled keys fail with the list of valid IDs
namelens check acmecorp --provider bogus
# error: unknown provider "bogus" (valid: namelens-anthropic, namelens-openai, namelens-xai)
```

Surfaced as a CLI ergonomics gap during a dogfood naming session where comparing
xAI vs Anthropic verdicts on the same name was awkward without the flag.

## `--expert` Provider Capability Divergence

**Status**: Documented

xAI's Grok models perform real-time web search by default; Anthropic's Claude
does **not**. For `check --expert`, the difference is material — a user
defaulting to Claude can get confident-but-shallow verdicts that miss recent or
niche conflicts (the dogfood session that produced the `--provider` flag also
surfaced this divergence: Grok found a real GSAP/contextsafe.es collision;
Claude returned "no conflicts found" on the same input).

New "Choosing a provider for `--expert`" section in `docs/ailink/README.md`
covers the gotcha and suggests cross-checking with multiple providers when
verdicts diverge.

A follow-up brief in `.plans/active/v0.3.0/` (private) tracks the broader
calibration work — either gate `--expert` on web-search capability or wire
Anthropic's web-search tool use into the AILink driver.

## Vulnerability Dependency Cleanup

**Status**: Fixed

`goneat dependencies --vuln` reported 12 findings on the previous tip (1
critical + 6 high + 5 medium):

- 11 in Go stdlib at `go1.26.1`. Cleared by adding `toolchain go1.26.2` to
  `go.mod`. Go auto-downloads the toolchain on demand, so local + CI builds use
  the patched stdlib regardless of the developer's installed Go. Clears
  [CVE-2026-27143](https://nvd.nist.gov/vuln/detail/CVE-2026-27143) (critical)
  and 10 others
- 1 in `golang.org/x/image v0.35.0`
  ([GHSA-44p7-9xx4-hf2g](https://github.com/advisories/GHSA-44p7-9xx4-hf2g),
  medium). Cleared by bumping to `v0.38.0`; pulls `golang.org/x/text v0.33.0` →
  `v0.35.0` transitively

Post-bump scan returns 0 findings.

## CI Infrastructure

**Status**: Changed

CI runner image bumped from `goneat-tools-runner-glibc:v0.3.1` to `v0.4.0`. The
v0.4.0 image bundles `golangci-lint v2.12.1` built against the runner's pinned
Go (1.26.2) — closes a recurring "user installs Go-built tool inside runner,
runtime mismatch with their config" failure pattern.

The redundant `golangci/golangci-lint-action@v7` install step was removed from
`.github/workflows/ci.yml` since the bundled binary is now present at
`/usr/local/bin/golangci-lint`. Keeping a separate install step would shadow the
bundled binary and reintroduce the version-mismatch class of bug.

## YAML Tooling Alignment

**Status**: Added

Added `.yamlfmt` and `.yamllint` configuration files at repo root with
`pad_line_comments: 2` set explicitly. Without this, three tools (yamlfmt,
yamllint, goneat) disagree on YAML inline-comment padding:

- `yamllint` default: 2 spaces before `#`
- `yamlfmt` default: 1 space before `#`
- `goneat` pin: 2 spaces (matches yamllint)

The disagreement causes CI oscillation — every regeneration alternates between
the two formats. Setting `pad_line_comments: 2` explicitly in `.yamlfmt` aligns
all three tools on the same value. See goneat appnote
[`yaml-format-lint-alignment`](https://crucible.3leaps.dev/) for the underlying
mechanism.

## `make api-generate` Idempotency

**Status**: Fixed

`oapi-codegen` overwrites `internal/api/openapi.gen.go` on every regen and
dropped the `// #nosec G101` suppression that earlier security work had added
inline (the `ApiKeyScopes` constant trips G101 even though it holds no
credential material). Result: `make check-api` was permanently dirty — every
regen re-introduced the unsuppressed finding.

Fixed by adding a perl post-step in the Makefile that re-injects the annotation
after `oapi-codegen` runs, so the generated file is byte-stable across
regenerations.

## errcheck Cleanup via `errWriter`

**Status**: Fixed

`internal/cmd/generate.go` had ~80 unchecked `fmt.Fprintf` / `fmt.Fprintln`
calls across the result renderers (`renderNameAlternativesResults`,
`renderSearchResponseResults`, etc.) and their helpers. errcheck flagged all of
them at lint time.

Refactored through a small `errWriter` helper that wraps an `io.Writer` and
captures the first write error, letting each renderer keep its inline write
sequence and return `ew.err` once at the end. Public signatures
(`renderGenerateResults`, `printGenerateRawFallback`) are unchanged so the
existing tests still drive the renderers via `bytes.Buffer`.

## Hooks Regenerated Without Guardian Intercept

**Status**: Changed

The team is moving from microteam direct-push to a PR-based workflow with branch
protection on the remote replacing the local approval prompt. Local `pre-commit`
and `pre-push` hooks were regenerated via `goneat hooks generate` (without
`--with-guardian`) so they no longer prompt for browser approval on each
commit/push.

The user-level guardian config at `~/.goneat/guardian/config.yaml` is unchanged
— other repos using guardian continue to be protected.

## `make pr-final` Strict Local Gate

**Status**: Added

New Makefile target that mirrors what GitHub Actions runs on a PR:

```bash
make pr-final
# Runs: goneat format
# Then:  goneat assess --check --categories format,lint,security \
#               --fail-on medium --format concise
# Then:  make check
```

Same shape as `make prepush` but stricter (`--fail-on medium` vs the `prepush`
default of `high`). Catches CI surprises locally before pushing PR updates.
Documented in `AGENTS.md` (new "Before Pushing PR Updates" section) and
`RELEASE_CHECKLIST.md`.

## Other Fixes

- **xAI driver: structured output preserved on tool calls** — fixed a regression
  where tool-call responses lost the response schema
- **AILink: short-domain tool mismatch fails fast** instead of silently
  returning incomplete results
- **`generate` renders prompt-specific structured output** matching the invoked
  prompt's schema (previously fell back to a generic shape for some prompt
  slugs)
- **Config layer repo-root validation** before using filesystem assets,
  preventing nil-path errors in standalone deployments
- **G115 / G101 security hardening**: integer overflow bounds checks on
  uint64→int64 timestamp, int→uint16 port, and int→uint32 PID conversions in
  daemon code; G101 false positive suppressed on generated `ApiKeyScopes`
  constant
- **QF1012 lint cleanup**: `WriteString(fmt.Sprintf(...))` → `fmt.Fprintf(...)`
  across `internal/ailink/context/corpus.go`, `internal/output/analysis.go`, and
  `internal/output/markdown.go`

## Prompt Updates

- **`name-offconcept`**: new hard-decorrelated name generator for cases where
  `name-alternatives` produces too-correlated candidates
- **brand-plan, brand-proposal, name-alternatives**: prompts generalized to
  reduce template-bound output
- **Configurable context budgets**: `--description-budget` and `--scan-budget`
  flags on `generate` cap how much description / scanned-file content is
  injected into the prompt

## Upgrade Notes

No breaking changes. All v0.2.3 configurations remain valid.

If your CI references `goneat-tools-runner-glibc:v0.3.5` or earlier, bump to
`:v0.4.0` and remove any separate `golangci-lint` install step — the runner now
ships a verified binary built against its pinned Go.
